LED COLOR INSPECTION – อัลกอริทึมการตรวจสี LED ด้วยกล้อง (Vision)
===================================================================

1. หลักการ
----------
กล้องถ่ายภาพแผง LED แล้วโปรแกรมตอบคำถามเดียวสำหรับ LED แต่ละดวง:
"ในวงกลม ROI ของดวงนี้ มีพื้นที่ที่มีสีถูกต้องมากพอ และคงอยู่นานพอ หรือไม่"

การตัดสินทำเป็น 3 ชั้นซ้อนกัน

  ชั้นพิกเซล  : พิกเซลนี้มีสีที่ต้องการหรือไม่ (ช่วง HSV)
  ชั้น ROI     : ในวง ROI มีพิกเซลที่ผ่านมากกว่าเกณฑ์ Area หรือไม่ → OK / NG ของเฟรมนั้น
  ชั้นเวลา     : ROI ต้อง OK ต่อเนื่องครบ Hold ภายในเวลา Timeout จึงถือว่า OK จริง


2. ทำไมใช้ HSV ไม่ใช้ RGB
-------------------------
ค่าสีของ LED ที่กล้องเห็นเปลี่ยนตาม exposure และแสงแวดล้อม ถ้าใช้ RGB ทั้งสามค่า R, G, B
จะเลื่อนพร้อมกัน ทำให้กำหนดช่วงยาก แต่ใน HSV

  H (Hue)        โทนสี 0–179 (สเกล OpenCV)  แดง 0 / 175–179, ส้ม 10–20, เหลือง 25–35,
                 เขียว 55–75, ฟ้า 85–95, น้ำเงิน 110–130, ม่วง/ชมพู 145–165
                 → แทบไม่เปลี่ยนเมื่อสว่างขึ้นหรือมืดลง ใช้แยก "สีอะไร"
  S (Saturation) ความสด 0–255 → LED ที่ติดจะสดมาก พื้นหลัง/พลาสติกจะซีด ใช้แยก LED ออกจากพื้นหลัง
  V (Value)      ความสว่าง 0–255 → LED ที่ดับมี V ต่ำ ค่า V min คือตัวคัด LED ดับออก

ข้อควรระวัง: สีแดงอยู่สองปลายของสเกล H (ใกล้ 0 และใกล้ 179) โปรแกรมไม่วนค่า
ต้องเลือกด้านเดียวตามที่ฮิสโทแกรมแสดง


3. โมเดล: กลุ่ม LED และ ROI
---------------------------
  - กลุ่ม (Group) คือชุด LED ที่มีสีเดียวกันและตรวจพร้อมกัน เช่น L-7SEG, R-7SEG, U-5DOT
    เพิ่ม ลบ เปลี่ยนชื่อได้ไม่จำกัด
  - แต่ละกลุ่มมีพารามิเตอร์ของตัวเอง
      ROI      วงกลมหนึ่งวงต่อ LED หนึ่งดวง (ตำแหน่งกึ่งกลาง x,y บนภาพแสดงผล)
      Radius   รัศมี ROI เท่ากันทั้งกลุ่ม
      H/S/V    ช่วง min–max ของแต่ละแชนแนล
      Area     จำนวนพิกเซลขั้นต่ำที่ต้องผ่านช่วงสี
  - พิกัด ROI เก็บบนภาพแสดงผลขนาด 680×906 ตอนตรวจจะสเกลกลับไปยังภาพจริงของกล้อง
    ด้วยอัตราส่วนเดียวกันทั้งแกน x และ y วงกลมจึงยังเป็นวงกลม


4. การตรวจหนึ่งเฟรม (ต่อ ROI หนึ่งวง)
-------------------------------------
  1) คำนวณตำแหน่งและรัศมีของ ROI บนภาพจริง
     cx = x × (กว้างภาพจริง / กว้างภาพแสดงผล), cy, r ทำนองเดียวกัน
  2) ตัดภาพสี่เหลี่ยม (2r × 2r) รอบจุดกึ่งกลางออกมา
  3) แปลงชิ้นภาพจาก BGR เป็น HSV
  4) เกณฑ์สี (thresholding) แบบช่วง: inRange(lower = (Hmin, Smin, Vmin), upper = (Hmax, Smax, Vmax))
     พิกเซล p ผ่านก็ต่อเมื่อเงื่อนไขทั้งสามเป็นจริงพร้อมกัน
        Hmin ≤ H(p) ≤ Hmax  และ  Smin ≤ S(p) ≤ Smax  และ  Vmin ≤ V(p) ≤ Vmax
     ได้ mask: พิกเซลที่ผ่าน = ขาว (255) ไม่ผ่าน = ดำ (0)
     (เป็นเกณฑ์คงที่ที่ผู้ใช้ตั้ง ไม่ใช่เกณฑ์อัตโนมัติแบบ Otsu จึงคาดเดาได้และตั้งต่อกลุ่มสีได้)
  5) AND กับ mask วงกลมรัศมี r → ตัดมุมของสี่เหลี่ยมทิ้ง เหลือเฉพาะในวง
  6) นับพิกเซลขาว = พื้นที่สว่างที่มีสีถูกต้อง
  7) ถ้า จำนวน > Area → ROI นี้ OK ในเฟรมนี้ (วาดวงเขียว)
     ถ้า จำนวน ≤ Area → NG ในเฟรมนี้ (วาดวงแดง)

ความหมายของ Area: ไม่ใช่เปอร์เซ็นต์ แต่เป็นจำนวนพิกเซลจริงของภาพกล้อง จึงขึ้นกับ
รัศมี ROI และระยะกล้อง ค่าที่ดีคือประมาณครึ่งหนึ่งของพื้นที่สว่างตอน LED ติดปกติ
เพื่อให้ LED หรี่หรือสีเพี้ยนตกลงมาต่ำกว่าเกณฑ์


5. การตัดสินตามเวลา – Hold และ Timeout
-------------------------------------
LED บางชนิด (แผงสแกน, PWM, ไฟกะพริบ) ไม่ได้ติดทุกเฟรม และกล้องเองก็มีสัญญาณรบกวน
การตัดสินจากเฟรมเดียวจึงไม่พอ step VISION CHECK จึงเก็บตัวอย่างทุก 100 ms และใช้

  Hold    (ms)  ROI ต้องได้ OK ต่อเนื่องกันนานเท่านี้ (0 หรือว่าง = OK เฟรมเดียวก็พอ)
  Timeout (ms)  เวลารอสูงสุด (ค่าเริ่มต้น 2000)

ขั้นตอน
  - ROI แต่ละวงมีตัวนับ "จำนวนตัวอย่าง OK ติดต่อกัน" เจอ NG หนึ่งครั้ง ตัวนับกลับเป็น 0
  - ตัวนับ × 100 ms ≥ Hold → ROI นั้น "ถึง Hold" และคงสถานะ OK ไว้จนจบ step
  - ROI ทุกวงถึง Hold → step PASS ทันที ไม่ต้องรอหมด Timeout
  - หมด Timeout แล้วยังมี ROI ที่ไม่เคยถึง Hold → step FAIL วงเหล่านั้นแสดงสีแดง

ตัวอย่าง Hold 300, Timeout 2000: ต้อง OK 3 ตัวอย่างติดต่อกัน ถ้า LED ติดดี step จบใน ~0.3 s
ถ้า LED กะพริบทุก 200 ms ตัวนับจะไม่เคยถึง 3 → FAIL หลัง 2 s

โหมดเข้มงวด (ไม่ติ๊ก "VISION CHECK pass rule" ในหน้า Setting): ROI ทุกวงต้อง OK ในทุกตัวอย่าง
ตลอด Timeout มีตัวอย่างเดียวหลุดก็ NG ใช้เมื่อต้องการจับไฟกะพริบ

ค่าสี H/S/V และ Area ตั้งครั้งเดียวต่อกลุ่มในโมเดล ส่วน Hold/Timeout ตั้งต่อ step
กลุ่มเดียวกันจึงตรวจซ้ำได้หลายครั้งด้วยเงื่อนไขเวลาต่างกัน


6. หน้า Vision – เครื่องมือหาค่าที่ถูกต้อง
----------------------------------------
  - ภาพซ้าย: กล้องสด + วง ROI ของกลุ่มที่เลือก สีของวงคือผลของเฟรมล่าสุด
    (ช่อง Hold บนแถวแท็บทำให้วงเป็นเขียวเฉพาะเมื่อ OK ต่อเนื่องครบเวลา เหมือน step จริง)
  - ภาพกลาง: ผลของ inRange บนทั้งเฟรม เห็นทันทีว่าช่วง HSV จับสีอะไรบ้าง
  - ตาราง Group/HSV: แต่ละกลุ่ม 3 แถว H, S, V
      Min / Max     ช่วงที่ตั้ง (แก้ในช่องได้)
      Selected      ค่า min–max ที่วัดได้จาก ROI ที่กำลังเลือก (วงเส้นประ)
      Unselected    ค่าที่วัดได้จาก ROI อื่นในกลุ่ม
      All           ค่าที่วัดได้จาก ROI ทั้งกลุ่ม
  - ฮิสโทแกรม H, S, V ของ ROI ที่เลือก: ยอดสูงคือสีของ LED ตั้ง min/max ให้ล้อมยอดนั้น

วิธีตั้งค่าที่แนะนำ
  1) เปิด LED วาด ROI ดูฮิสโทแกรม H → ตั้ง H min/max รอบยอดหลัก ±8
  2) S min ≈ 80–120, S max = 255 (LED ขาว: S 0–60)
  3) V min ≈ 100–150, V max = 255
  4) ดับ LED แล้วตรวจว่า จำนวนพิกเซลผ่าน < Area ถ้าไม่ ให้เพิ่ม V min หรือ Area
  5) ตรวจว่าสีอื่นในกลุ่มเดียวกันไม่ตกในช่วง H นี้ สีใกล้กัน (ส้ม/เหลือง) ให้แยกกลุ่ม


7. ผลลัพธ์และภาพบันทึก
----------------------
  - ระหว่าง step แสดงเฉพาะ ROI ของกลุ่มที่ตรวจ จบ step ซ่อน จบรอบแสดง ROI ทุกวง
    พร้อมสีสรุป: เขียว OK, แดง NG, เทา ไม่ได้ตรวจ
  - ทุก step VISION CHECK ที่จบ โปรแกรมบันทึกภาพกล้อง + วง ROI ไว้ แล้วต่อเป็นภาพเดียว
    (แถบชื่อ step / ค่า / PASS-FAIL อยู่บนแต่ละภาพ) ใช้ตรวจย้อนหลังว่า NG เพราะดวงไหน
  - ค่า Value ของ step แสดงเป็น "จำนวน ROI ที่ OK / จำนวนทั้งหมด" เช่น 42/42 OK


8. ข้อจำกัดที่ควรรู้
--------------------
  - การตรวจอาศัยสีเท่านั้น ไม่วัดความสว่างสัมบูรณ์ LED หรี่ที่ยังผ่านช่วง HSV และ Area จะถือว่า OK
  - ค่ากล้องต้องคงที่ (ปิด Auto exposure / Auto WB / Auto focus) โปรแกรมเขียนค่าจากโมเดลลงกล้อง
    ทุกครั้งที่เปิดโมเดล
  - แสงสะท้อนจากตัวเครื่องอาจนับเป็นพิกเซลผ่าน แก้ด้วยลดรัศมี ROI หรือเพิ่ม Area
  - ROI ผูกกับตำแหน่งบนภาพ ถ้าจิ๊กเลื่อนหรือกล้องขยับ ต้องแก้ ROI หรือใช้ Pan/Tilt ของกล้องปรับกลับ
