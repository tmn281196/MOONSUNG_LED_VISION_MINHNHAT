LED COLOR INSPECTION — IO Box protocol

Serial protocol between the LED COLOR INSPECTION app (PC, LED Vision/DeviceControl.cs) and the IO Box firmware SystemControl/System/System.ino (Arduino Mega 2560). One test station: one 220 V power relay for the product, one pneumatic cylinder (UP / DOWN valves, one DOWN sensor) and five general-purpose relays.
BoardArduino Mega 2560
Port9600 8N1
Frame4 bytes, both directions: cmd key value 11
Terminator11 — a frame whose 4th byte is not 0x11 is dropped one byte at a time until the parser resyncs
Checksumnone

§1 · Frame format

cmdwhat
keywhich one
valuestate / level
11terminator

Every frame is a key / value pair: cmd says what kind of thing is being addressed, key which one, value its state. The board answers a command by echoing the same frame (SET, RESET) or by sending one frame per input (GET). Both sides use exactly the same layout, so a serial monitor shows the conversation as pairs of 4-byte lines.

§4 · GET — 0x49, inputs

ActionTXRX
Read all inputs49 00 00 1149 01 u 11 then 49 02 d 11

keyInputPinlevel
1UP sensor (reserved, not fitted)3raw pin level, INPUT_PULLUP

The app sends a GET right after opening the port so it knows where the cylinder is. After that it relies on the event frame: the board sends 49 02 level 11 by itself every time the DOWN sensor changes, after a 50 ms debounce. A 0 → 1 change is the test trigger; a 1 → 0 change during a test cancels it.

§5 · Interlocks and power-on state

  • At power-on every output (POWER, UP_OUT, DOWN_OUT, RELAY 1..5) is LOW.
  • POWER can only be switched ON while the DOWN sensor is active. A 52 00 01 11 arriving while the cylinder is not down is applied as OFF; the echo is still 52 00 01 11.
  • When the DOWN sensor releases the board cuts POWER by itself, before the PC even receives the event frame.
  • The five relays have no interlock; they keep their state until commanded, RESET, or the board is reset.
The board never times out an output. If the PC disconnects while POWER or a relay is ON, it stays ON. Send D5 00 00 11 when your software starts and when it exits.

§7 · How the app drives a test

  1. Event 49 02 01 11 (cylinder reached the bottom) or the START button → test starts. Events during a test, and for 1.5 s after it ends, are ignored.
  2. Wait for DOWN sensor (Sensor timeout) → Before power ON delay → 52 00 01 11 → After power ON delay → camera check.
  3. NG → retest: 52 00 00 11, 52 01 01 11, wait for the DOWN sensor to release, Delay between UP / DOWN, 52 01 00 11, 52 02 01 11, wait for the DOWN sensor, Before power ON, 52 00 01 11, After power ON, check again.
  4. End or EMERGENCY STOP → POWER, UP_OUT and DOWN_OUT off (three SET frames).
