LED COLOR INSPECTION — IO Box protocol

Serial protocol between the LED COLOR INSPECTION app (PC, LED Vision/DeviceControl.cs) and the IO Box firmware SystemControl/System/System.ino (Arduino Mega 2560). One test station: one 220 V power relay for the product, one pneumatic cylinder (UP / DOWN valves, one DOWN sensor) and five general-purpose relays.
โปรโตคอลอนุกรมระหว่างโปรแกรม LED COLOR INSPECTION (PC, LED Vision/DeviceControl.cs) กับเฟิร์มแวร์ IO Box SystemControl/System/System.ino (Arduino Mega 2560) สถานีทดสอบ 1 ชุด: รีเลย์ไฟ 220 V ของชิ้นงาน 1 ตัว, กระบอกลม 1 ตัว (วาล์ว UP / DOWN, เซ็นเซอร์ DOWN 1 ตัว) และรีเลย์อเนกประสงค์ 5 ตัว
Boardบอร์ดArduino Mega 2560
Portพอร์ต9600 8N1
Frameเฟรม5 bytes, both directions5 ไบต์ ทั้งสองทิศทาง: cmd key value chk 11
Checksumเช็คซัมchk = cmd XOR key XOR value
Terminatorไบต์ปิดท้าย 11 — a frame whose checksum is wrong or whose 5th byte is not 0x11 is dropped one byte at a time until the parser resyncs — เฟรมที่เช็คซัมผิดหรือไบต์ที่ 5 ไม่ใช่ 0x11 จะถูกทิ้งทีละไบต์จนกว่าตัวแยกเฟรมจะซิงค์ใหม่ได้

§1 · Frame format

§1 · รูปแบบเฟรม

cmdwhatทำอะไร
keywhich oneตัวไหน
valuestate / levelสถานะ / ระดับ
chkcmd ^ key ^ value
11terminatorไบต์ปิดท้าย

Every frame is a key / value pair: cmd says what kind of thing is being addressed, key which one, value its state. chk is the XOR of the three bytes before it; a receiver recomputes it and drops the frame if it differs. The board answers a command by echoing the same frame (SET, RESET) or by sending one frame per input (GET). Both sides use exactly the same layout, so a serial monitor shows the conversation as pairs of 5-byte lines.

ทุกเฟรมคือ คู่ key / value: cmd บอกว่ากำลังจัดการกับอะไร, key บอกว่าตัวไหน, value คือสถานะของมัน chk คือค่า XOR ของ 3 ไบต์ก่อนหน้า ฝ่ายรับจะคำนวณใหม่แล้วทิ้งเฟรมถ้าค่าไม่ตรง บอร์ดตอบคำสั่งด้วยการส่งเฟรมเดิมกลับ (SET, RESET) หรือส่ง 1 เฟรมต่อ 1 อินพุต (GET) ทั้งสองฝั่งใช้รูปแบบเดียวกันทุกประการ ดังนั้นใน serial monitor จะเห็นการสนทนาเป็นคู่บรรทัด 5 ไบต์

The app sends a GET right after opening the port so it knows where the cylinder is. After that it relies on the event frame: the board sends 49 02 level chk 11 by itself every time the DOWN sensor changes, after a 50 ms debounce. A 0 → 1 change is the test trigger; a 1 → 0 change during a test cancels it.

โปรแกรมส่ง GET ทันทีหลังเปิดพอร์ตเพื่อให้รู้ว่ากระบอกอยู่ตำแหน่งไหน หลังจากนั้นจะอาศัยเฟรม event: บอร์ดส่ง 49 02 level chk 11 เองทุกครั้งที่เซ็นเซอร์ DOWN เปลี่ยน หลังหน่วง debounce 50 ms การเปลี่ยน 0 → 1 คือสัญญาณเริ่มทดสอบ ส่วนการเปลี่ยน 1 → 0 ระหว่างทดสอบจะยกเลิกการทดสอบ

§5 · Interlocks and power-on state

§5 · อินเตอร์ล็อกและสถานะตอนเปิดเครื่อง

  • At power-on every output (POWER, UP_OUT, DOWN_OUT, RELAY 1..5) is LOW.
  • POWER can only be switched ON while the DOWN sensor is active. A 52 00 01 53 11 arriving while the cylinder is not down is applied as OFF; the echo is still 52 00 01 53 11.
  • When the DOWN sensor releases the board cuts POWER by itself, before the PC even receives the event frame.
  • The five relays have no interlock; they keep their state until commanded, RESET, or the board is reset.
  • ตอนเปิดเครื่อง เอาต์พุตทุกตัว (POWER, UP_OUT, DOWN_OUT, RELAY 1..5) เป็น LOW
  • POWER เปิด ON ได้เฉพาะขณะเซ็นเซอร์ DOWN ทำงาน ถ้า 52 00 01 53 11 มาถึงขณะกระบอกไม่ได้อยู่ล่าง จะถูกใช้เป็น OFF แต่เฟรมตอบกลับยังคงเป็น 52 00 01 53 11
  • เมื่อเซ็นเซอร์ DOWN หลุด บอร์ดจะตัด POWER เอง ก่อนที่ PC จะได้รับเฟรม event เสียอีก
  • รีเลย์ทั้ง 5 ตัวไม่มีอินเตอร์ล็อก คงสถานะไว้จนกว่าจะได้รับคำสั่ง, RESET หรือรีเซ็ตบอร์ด
The board never times out an output. If the PC disconnects while POWER or a relay is ON, it stays ON. Send D5 00 00 D5 11 when your software starts and when it exits.
บอร์ดไม่มีการหมดเวลาของเอาต์พุต ถ้า PC หลุดการเชื่อมต่อขณะ POWER หรือรีเลย์เป็น ON มันจะค้าง ON ต่อไป ให้ส่ง D5 00 00 D5 11 ตอนซอฟต์แวร์เริ่มทำงานและตอนปิดโปรแกรม

§7 · How the app drives a test

§7 · โปรแกรมควบคุมการทดสอบอย่างไร

  1. Event 49 02 01 4A 11 (cylinder reached the bottom) or the START button → test starts. Events during a test, and for 1.5 s after it ends, are ignored.
  2. Wait for DOWN sensor (Sensor timeout) → Before power ON delay → 52 00 01 53 11 → After power ON delay → camera check.
  3. NG → retest: 52 00 00 52 11, 52 01 01 52 11, wait for the DOWN sensor to release, Delay between UP / DOWN, 52 01 00 53 11, 52 02 01 51 11, wait for the DOWN sensor, Before power ON, 52 00 01 53 11, After power ON, check again.
  4. End or EMERGENCY STOP → POWER, UP_OUT and DOWN_OUT off (three SET frames).
  1. Event 49 02 01 4A 11 (กระบอกลงถึงล่างสุด) หรือปุ่ม START → เริ่มทดสอบ event ระหว่างทดสอบและภายใน 1.5 วินาทีหลังจบจะถูกละเว้น
  2. รอเซ็นเซอร์ DOWN (Sensor timeout) → หน่วง Before power ON → 52 00 01 53 11 → หน่วง After power ON → ตรวจด้วยกล้อง
  3. NG → ทดสอบซ้ำ: 52 00 00 52 11, 52 01 01 52 11, รอเซ็นเซอร์ DOWN หลุด, Delay between UP / DOWN, 52 01 00 53 11, 52 02 01 51 11, รอเซ็นเซอร์ DOWN, Before power ON, 52 00 01 53 11, After power ON, ตรวจอีกครั้ง
  4. จบหรือ EMERGENCY STOP → ปิด POWER, UP_OUT และ DOWN_OUT (เฟรม SET 3 เฟรม)
