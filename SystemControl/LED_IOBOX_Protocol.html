LED COLOR INSPECTION — IO Box protocol

Serial protocol between the LED COLOR INSPECTION app (PC, LED Vision/DeviceControl.cs) and the IO Box firmware SystemControl/System/System.ino (Arduino Mega 2560). One test station: one 220 V power relay for the product, one pneumatic cylinder (UP / DOWN outputs, one DOWN sensor) and five general-purpose relays.

§1 · Frame format

TX PC → IO Box (10 bytes, every command)

The size byte is the number of bytes from cmd to d3 plus one, always 06 for the commands below. The firmware starts parsing when it sees 44, reads until it has 10 bytes, then dispatches on byte 3 (cmd). Bytes after the 10th are discarded. The firmware does not verify the checksum today; the PC always sends a correct one so a future firmware may enforce it.

RX IO Box → PC, command ack (6 bytes)

45prefix 2

Sent after every accepted output command (4F and 52). Fixed content, no checksum. The PC does not wait for it.

The board sends this frame by itself every time the DOWN sensor changes (after a 50 ms debounce), and on request (§2). The PC reads only bits 0 and 1; other bits of in are undefined. Frames shorter than 7 bytes are dropped by the PC.

Set ALL outputs — 0x4F (legacy)

Kept for older PC software. d3 carries the three cylinder-station bits; d0..d2 are unused. This command does not touch the five relays.

Request input — 0x49

A frame whose byte 2 is 49 makes the board answer with the current input frame immediately. The app does not use it; the unsolicited event frame is enough.

§4 · Interlocks and power-on state

  • At power-on every output (POWER, UP_OUT, DOWN_OUT, RELAY 1..5) is LOW.
  • POWER can only be switched ON while the DOWN sensor is active. A POWER ON command arriving while the cylinder is not down is turned into OFF.
  • When the DOWN sensor releases (cylinder leaves the bottom) the board cuts POWER by itself, before the PC even receives the event frame.
  • The five relays have no interlock; they keep their state until commanded or until the board is reset.
The board never times out an output. If the PC disconnects while POWER or a relay is ON, it stays ON. The app sends all-off frames when a test ends or is cancelled; if you write your own host software, do the same.

§6 · How the app drives a test

  1. DOWN sensor event (bit 1 goes 0 → 1) or the START button → test starts. Events during a test, and for 1.5 s after it ends, are ignored.
  2. Wait for DOWN sensor (Sensor timeout) → Before power ON delay → POWER ON (index 0) → After power ON delay → camera check.
  3. NG → retest: POWER OFF, UP_OUT on, wait for the DOWN sensor to release, Delay between UP / DOWN, UP_OUT off, DOWN_OUT on, wait for the DOWN sensor, Before power ON, POWER ON, After power ON, check again.
  4. End or EMERGENCY STOP → POWER OFF, UP_OUT off, DOWN_OUT off.
